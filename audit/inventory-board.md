# Inventory: Board, plot lines, markers, scene plan (read-only audit)

Scope: `src/views/BoardView.tsx`, `src/components/{ScenePlan,StoryLine,Plot,HeroBranches,MarkerCard,ColorDot,ChapterMeter,LeftToWrite}.tsx`, `src/styles/line.css`. Followed into `src/db/repo.ts`, `src/lib/ui.tsx` (InlineEdit, Modal, toast), `src/lib/hooks.ts`, `src/components/Refs.tsx` (RefChips, PlacePicker), `src/components/SceneEditor.tsx` (autosave), `src/App.tsx` (global keys).

Conventions:
- "repo.X" means a function in `src/db/repo.ts`. `save()` is a Dexie transaction (table + outbox) followed by `notifyChange()`. All "soft deletes" are `patch(..., {deleted:true})`.
- Undoable: "no" = no undo toast and no Ctrl+Z path. `toast(msg, undo)` supports an undo button, but nothing in the assigned files passes one. `repo.arrangeScenes` returns an undo closure but is never called anywhere (dead export).
- Global keyboard shortcuts in the app (`App.tsx:99-108`): only Ctrl/Cmd+J (quick capture) and Ctrl/Cmd+Shift+F (search). There is no Ctrl+Z / Ctrl+Y handler for board, plan or marker operations. Ctrl+Z only works inside the TipTap editor.
- Kbd column: yes / no / partial.
- Rows B-044, B-067, B-068, B-097, B-098 describe code reached through imports (`ui.tsx`, `Refs.tsx`) from the assigned files; the rest are in the assigned files themselves.

## Defects found

Evidence lines are quoted from the files above.

### BUG

- **B-054 / B-055: scenes can leave a locked chapter in the line layout.** `StoryLine.start()` and `drop()` only test the destination (`c.locked` inside `target()`), never the source chapter. The columns board refuses this (`isLocked(data, from)`, BoardView.tsx:100), so «Глава зафиксирована — сцены в ней не двигаются» is only true for one of the two layouts. Evidence: `if (!c || c.locked || py > H + 8) return null` (StoryLine.tsx:133); `await moveScene(id, t.c.id, ...)` with no `isLocked` call (L151, L144).
- **B-054: wrong insert index when the hidden «Первая сцена» placeholder is in the target chapter.** `old` is filtered by `!isPlaceholder`, so `slot` counts visible scenes only, but `moveScene` splices into the full sibling list (which includes the placeholder). Dropping at visible slot N puts the scene at visible position N-1. Evidence: `.filter((x) => !isPlaceholder(x, data))` (L149) then `moveScene(id, t.c.id, was !== -1 && t.slot > was ? t.slot - 1 : t.slot)` (L151).
- **B-053: touch drag leaves stuck state.** `touch-action: pan-x` on the svg (line.css:52) lets the browser take over a horizontal touch drag and fire `pointercancel`; the effect only listens to `pointermove`/`pointerup` (StoryLine.tsx:121-122), so `drag` is never cleared and the ghost/lifted visuals remain until another pointerup. No Escape cancel either.
- **B-017: keyboard users cannot open a scene on the columns board.** The sortable div gets role=button/tabIndex=0 from dnd-kit, but Enter/Space are claimed by `KeyboardSensor` to start a drag, and the only open handler is `onClick={onOpen}` (L680). In locked chapters no key does anything.
- **B-075: chapter split can lose the tail text.** Order of writes: `setContent(head)`, `save(texts head)`, `patch(scene counts)`, only then `createScene(... tail)`. If any later call throws, the tail exists only in editor history. No try/catch. Afterwards Ctrl+Z in the editor brings the tail back into the old scene while the new chapter still exists, duplicating text.
- **B-109: restoring a version leaves scene counters stale.** `editor.commands.setContent(content as object, { emitUpdate: false })` (ScenePlan.tsx:474) skips the editor flush that patches `scenes.wordCount/charCount/excerpt` (`SceneEditor.tsx:136`). Board cards, chapter length and progress keep the pre-restore numbers.
- **B-110: scene merge loses or orphans data.** `mergeSceneIntoPrevious` remaps `setupSceneId/payoffSceneId` but not `echoSceneIds`, `notes.sceneId`, goal/excerpt; reads `db.texts` (not live editor state); `if (a) await save(...)` drops the merged text if the previous scene has no text row.
- **B-027: «Склеить с предыдущей главой» has no confirm and no undo** and discards the merged chapter's title/goal/deadline (`onClick={() => void mergeIntoPrevious(chapter.id).then(() => toast(...))}`, BoardView.tsx:385).
- **B-020: chapter title can be saved empty.** `onSave={(title) => void patch<Chapter>('chapters', chapter.id, { title })}` (L345) has no trim/empty guard, unlike the line name (L491).
- **B-013: empty line name leaves UI/DB mismatch.** `name.trim() && void patch(...)` does nothing for empty input but InlineEdit keeps `v=''`, so the field shows blank while the stored name is unchanged.
- **B-021: ⋯ menu never closes.** `<details className="menu">` (L360) has no close-on-action, outside-click or Escape logic.
- **B-035: «Разложить по частям» overwrites a custom title and can double-fire.** `patch(first.id, { title: 'Начало', ... })` is unconditional (L645); the button stays rendered until the live query refreshes, so a double click makes two «Середина»/«Финал».
- **B-047: «Замысел» panel disappears when the last field is cleared** (`if (!embedded && !filled) return null`, Plot.tsx:75) and the empty-state text at L101 is unreachable.
- **B-048: unguarded `sessionStorage`** at BoardView.tsx:62-63 can throw and crash the board; the rest of the app wraps storage in try/catch.
- **B-074: Escape in ColorDot also closes an enclosing Modal** (document keydown at ColorDot.tsx:28 and window keydown at ui.tsx:41 both fire).

### RACE

- **B-008, B-096:** `createLine` / `createMarker` are awaited before the input is cleared, so a fast second Enter creates a duplicate (`const l = await createLine(...)`, then `setNewLine(null)`, BoardView.tsx:210-211; `await createMarker(...)`, then `setV('')`, ScenePlan.tsx:300-301).
- **B-062:** HeroBranches `apply` is not guarded against double click and uses stale `data.lines` / `data.sceneById`, so duplicate lines and overwritten `lineIds` are possible.
- **B-079:** «Завести ещё N» loops with a stale `data.chapters.length`; a double click doubles the chapters.
- **B-108 / B-110:** snapshot and merge read the saved text, not the live editor (autosave debounce 800 ms, `SceneEditor.tsx:107`).
- **B-111:** after delete the still-mounted editor may flush a pending autosave and re-write the text row without `deleted`.
- **B-098:** Escape in RefChips input only sets `adding=false`; if the browser fires blur when the input unmounts, `add()` runs with the typed name.

### NO-ERROR-HANDLING

All fire-and-forget (`void`) or un-caught awaits with no user feedback on failure: B-008, B-009, B-010, B-015, B-016, B-024, B-025, B-026, B-027, B-028, B-030, B-031, B-034, B-035, B-036, B-041, B-042, B-049, B-054, B-055, B-056, B-058, B-062, B-063, B-071, B-075, B-079, B-096, B-098, B-100, B-103, B-109, B-110, B-111. Typical evidence: `void moveScene(sceneId, chapterId, count)` (BoardView.tsx:110); `setDraft('')` before `await createScene(...)` (L328-329) so the typed text is lost if the write fails. Multi-record operations (`moveScene`, `mergeIntoPrevious`, `deleteChapter`, `mergeSceneIntoPrevious`, `reorderChapters`) are sequential `save()` calls, not one transaction, so a mid-way failure leaves a half-applied state. `moveScene` also silently clears `scene.together` on the moved scene or its follower.
