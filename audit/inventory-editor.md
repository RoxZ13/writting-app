# Инвентарь взаимодействий: экран «Текст» (редактор) и связанные компоненты

Область: `src/views/WriteView.tsx`, `src/components/{SceneEditor,SceneSheet,FindBar,Focus,MarginNotes,QuickCapture,TypoControls,Refs,WhereFound,SearchModal,Shortcuts,TextStats}.tsx`, `src/components/{EditHints,InlineNote,CommentMark,MarkerMark,FindHighlight,Typography}.ts`, плюс то, что они вызывают: `src/lib/{typograf,typography,editcheck,session,sprint,search,hooks,ui,router,diff,text,pace}.ts*`, `src/db/{repo,sync,cloud}.ts`, глобальные клавиши из `src/App.tsx`.
Режим: только чтение, исходники не менялись. Дата аудита: 2026-10-18.

Условные обозначения. «kbd» = доступно с клавиатуры. «undo» = можно отменить. Значения suspicion: OK, BUG, DEAD, MISMATCH, NO-ERROR-HANDLING, A11Y, RACE, DATA-LOSS-RISK, UNCLEAR. Первый токен в колонке — главный тип. Номера строк — по состоянию файлов на момент аудита (ветка `claude/editor-and-board-redesign`).

Общее про диалоги: все модалки (`Modal` в `src/lib/ui.tsx:39-52`) закрываются по Esc (window keydown) и по mousedown на фон; фокус внутрь не переносится и не возвращается, фокус-ловушки нет. Это относится к строкам, где указано «Modal».

## Save path

Точные места и порядок событий для текста сцены (файл `src/components/SceneEditor.tsx`, запись в `src/db/repo.ts`).

1. Набор текста -> `onUpdate` (SceneEditor.tsx:101-108): `latest.current = editor.state` (:102); при первом изменении после сохранения `onSaved(false)` (:104); `dirty.current = true` (:105); `clearTimeout` + `setTimeout(flush, 800)` (:106-107). Это единственный постоянный триггер «по таймеру». В IndexedDB в этот момент ничего не пишется. `onUpdate` в TipTap React берётся из актуального рендера (node_modules/@tiptap/react/dist/index.js:312-314), так что замыкание не устаревает.
2. `flush()` (:111-138), фаза 1: `clearTimeout`; `state = latest.current ?? ed.state`; выходит, если `!dirty` (:114); `dirty = false` (:115) ДО записи; `saving = true`; `content = state.doc.toJSON()`; `await save('texts', { ...initial, content, wordCount })` (:121). `save` (repo.ts:21-29): `updatedAt = Date.now()`, транзакция rw над `texts` и `outbox`, `put`, потом `notifyChange()` -> `scheduleSync` (cloud.ts:132). После записи: `lastSavedAt = saved.updatedAt` (:122), `finally { saving = false }` (:124), `onSaved(true)` если за это время не было новых правок (:126), `onWords` (:127).
3. `flush()` фаза 2 (:128-137): `db.scenes.get` -> `recordWords(delta)` (pace.ts:16-21, накапливает в памяти, запись через 2 с; у pace.ts:40 есть `pagehide`-сброс) -> `patch('scenes', {wordCount, charCount, lastPos, excerpt})` (:136). Это отдельная запись; между фазами нет транзакции.
4. Другие триггеры: (a) `visibilitychange` в состоянии 'hidden' (:158-159); (b) `pagehide` (:160) — тот же обработчик с проверкой `visibilityState==='hidden'`, которое по спецификации в момент `pagehide` ещё может быть 'visible' (BUG, E-006; рабочим остаётся `visibilitychange`); (c) размонтирование (:161-171): при `dirty` — `flush(editor)`, иначе только патч `lastPos`. Размонтирование происходит при смене сцены (`<WriteView key={textScene}>`, App.tsx:171), переходе на доску/в настройки, кнопке «Назад»; редактор уничтожается TipTap через 1 мс (index.js `scheduleDestroy`), поэтому `flush` пользуется сохранённым `latest`, а не `editor.state`.
5. Не сохраняют: потеря фокуса редактора (обработчика onBlur нет), Ctrl+S (не привязан, откроется системное «Сохранить страницу»), `beforeunload` (нет).
6. Вывод по сценариям:
   - Набрал и сразу переключил сцену (кнопка в навигаторе, Ctrl+Alt+↑/↓, Назад): текст пишется в cleanup (:165). Для обычного пути потери нет. Условие: запись не должна упасть (п. 7a).
   - Набрал и сразу закрыл вкладку/перезагрузил: окно до 800 мс; страхуется только асинхронным `flush` в `visibilitychange`, который при выгрузке страницы не гарантирован (транзакция IndexedDB может не успеть); предупреждения при закрытии нет. DATA-LOSS-RISK умеренный.
   - Свернул окно/переключил вкладку: `visibilitychange` -> `flush`, надёжно.
7. Отдельные риски:
   a. Нет catch в `flush`: `dirty` обнулён до записи, при ошибке (квота, закрытая БД, режим приватности) исключение уходит в `unhandledrejection`, значок остаётся «Сохраняю…», повторной попытки нет до следующего нажатия клавиши, а flush при размонтировании пропускается (`dirty=false`) — текст пропадает молча (E-003).
   b. Синхронизация против несохранённого: `syncOnce` (sync.ts:41-44) при пустом outbox делает `table.put(row.data)` поверх локального текста, пока в редакторе есть несохранённые правки; эффект подмены (:177-187) при `dirty` не срабатывает и не перезапускается, следующий `flush` затирает чужую версию без снимка (снимок «конфликта» создаётся только когда запись уже в outbox, sync.ts:47-65) (E-009).
   c. Подмена из БД проходит через `setContent` в истории редактора: Ctrl+Z вернёт старый текст и его же сохранит поверх (E-009).
   d. `flush` строит запись из `...initial` первого рендера (:121): поля из `initial`, изменённые позже на уровне БД (например, `deleted` при удалении сцены на другом устройстве), будут перезаписаны.
   e. Операции «Переписать» (E-076, E-084) делают снимок из БД (`db.texts.get`), а не из редактора — набранное за последние ~0.8 с в снимок не попадает; `StartRewrite` пишет в БД пустой текст напрямую и `setContent(..., emitUpdate:false)`, не сбрасывая `dirty`/`latest`, поэтому отложенный `flush` способен вернуть старый текст.
   f. Запись «какая сцена открыта»: `patch('projects', {lastSceneId})` при каждом открытии (WriteView.tsx:232) — отдельная запись, не связана с текстом.
   g. `patch()` (repo.ts:31-35) читает и пишет не в одной транзакции: одновременные `patch` одной записи (flush сцены + правка названия) могут перетереть друг друга.

## Questions for the owner

1. Привычка нажимать Ctrl+S для тебя актуальна? Сейчас клавиша ничего не сохраняет и открывает диалог браузера «Сохранить страницу». Привязать её к немедленному сохранению сцены?
2. Допустимо ли окно до 0.8 с без записи при закрытии вкладки/перезагрузке? Можно сократить таймер, писать по каждому слову, добавить предупреждение при закрытии или копию в localStorage.
3. Что должно происходить при ошибке записи в базу (квота, приватный режим): показывать явную красную плашку, не закрывать сцену, предлагать скачать текст?
4. Режим «Переписать» хранится глобально в браузере. Должен ли он быть привязан к сцене (включаться только там, где есть `rewriteFrom`)?
5. Поиск по истории: искать ли в сцене «Пока без места»? Должен ли клик по результату вести именно на выбранное вхождение, а не на первое в сцене?
6. «Быстрая запись» на телефоне: где ей быть на экране «Текст», раз кнопки `fab` там нет и Ctrl+J недоступна?
7. Esc и клик по фону закрывают модалки без вопроса. Хочешь ли ты защиту от потери набранного в «Быстрой записи», «Заметке на полях», «Записке себе»?
8. Метки маячков и заметок копируются вместе с текстом и размножаются при вставке. Нужно ли снимать их при вставке?
9. Подтверждение удаления сцены и склейки есть, но восстановления нет. Нужна ли корзина или кнопка «Отменить» в тосте?
10. Вставка текста всегда проходит через типографику без возможности отключить. Нужна ли команда «вставить как есть» (Ctrl+Shift+V)?
11. Должны ли нижележащие возможности StarterKit (подчёркивание, ссылки, списки, цитаты, мягкий перенос) оставаться? Их нет в «Горячих клавишах».
12. Пункт меню «Найти и заменить» подписан «Ctrl+F»; поправить подпись на Ctrl+H или объединить обе комбинации?
13. Нужно ли при архивировании заметки в плане сцены (ScenePlan.tsx:167) снимать метку в тексте, как это делает окно заметки (WriteView.tsx:1065)?
