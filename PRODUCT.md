# Product

## Platform

web

PWA: работает в браузере, ставится на устройство, работает без сети.

## Users

Авторы больших нелинейных историй: фанфиков и любовных романов. Многие с СДВГ. Они теряют нить сюжета, перегружаются от лишних полей и бросают планирование, если оно мешает писать.

Владелец пишет сам и планирует так: любимые герои → яркие сцены с ними → события и переходные главы между сценами → маячки ко всему, чтобы перечитывать было интересно.

## Product Purpose

Рабочий стол автора. В любой момент видно, что я сейчас пишу, зачем, и какие маячки ещё ждут раскрытия.

Успех: автор пишет, а не ведёт учёт. Текст не теряется никогда.

## Positioning

Планирование выводится из того, что автор уже сделал, а не из полей, которые он должен заполнить. Маячок рождается из сцены, где он раскрывается, и сам подсказывает, где его посеять. Порядок сцен защищают маячки, а не ручные проверки.

## Operating Context

- Автор пишет сценами. Главы собирает из сцен позже и часто пересобирает.
- Публикация глав на Фикбуке. Импорт выгрузки Фикбука .txt: шапка, «========== Часть N ==========», сцены через `***`.
- Импорт и экспорт Word .docx.
- Синхронизация между устройствами — через Яндекс Диск. Supabase в коде есть, но для авторов это не рабочий путь.

## Capabilities and Constraints

Решения от 2026-10-11 — эталон поведения. Где README с ними расходится, README устарел.

- Линии на доске — сюжетные линии (2–4), а не линия на каждого героя. Герои — маленькие аватары-буквы на карточках; клик по герою подсвечивает его сцены.
- Карточка сцены — стикер; может входить в 2–3 линии. Перетаскивать приятно, визуально минимально.
- Главы собираются из выбранных колонок («Сделать главой»). Края глав перетаскиваются. Всё отменяется через Ctrl+Z.
- Маячки на доске скрыты по умолчанию (счётчик), видны при выборе сцены или линии. Тихая пометка, если маячок стоит после своего раскрытия, с названием обеих сцен.
- Темп — только две необязательные пометки: «спокойная» / «напряжённая». Пятиточечного «накала» нет. «Ключевая сцена» — ручная тихая пометка, автоматического ◆ нет.
- Новая история открывает пропускаемый экран «Об истории» с кнопками «Придумать сцены» / «Сразу писать».
- Вид доски (линии или колонки глав) выбирается в Настройках, а не на панели.
- Во время письма ничего не уводит автора из текста.
- Всё пишется на устройство сразу (IndexedDB), работает без сети.

Не решено:
- вид планирования на телефоне;
- где живёт «Замысел»;
- ручная связь «держать рядом»;
- окончательное имя маячка (намёк / крючок);
- основные устройства авторов — неизвестно; проверять Windows Chrome и iPhone Safari как самые вероятные и самые рискованные;
- продаётся ли приложение (в README есть «покупатели»).

## Evidence on Hand

- Настоящая рукопись для проверок на объёме: выгрузка Фикбука, 124 тысячи слов, 17 частей. Лежит вне репозитория, в репозиторий не попадает.
- Отзывов, клиентов и цифр использования нет. Не выдумывать.

## Product Principles

1. Текст автора не теряется ни при каких условиях.
2. Выводить, а не спрашивать: информация берётся из сделанного, а не из новых полей.
3. Прятать по умолчанию, показывать при выборе.
4. Не уводить из текста во время письма.
5. Проверять на настоящем объёме, прежде чем строить сверху.

## Accessibility & Inclusion

Аудитория с СДВГ: мало одновременных сигналов, без мигания и отвлекающих подсказок во время письма, всё обратимо. Работа с клавиатуры — для письма это основной ввод.
