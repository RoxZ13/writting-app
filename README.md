# Manuscript.

Рабочий стол автора для тех, кто пишет большие нелинейные истории и теряет нить.
Главная задача — чтобы в любой момент было видно **что я сейчас пишу, зачем, и какие маячки ещё ждут раскрытия**.

Работает в браузере и устанавливается как приложение на iPhone, iPad, Mac и Windows. Без интернета — тоже.

## Как устроено

Одна книга — одно рабочее место. Сверху три вкладки: **Текст · Доска · Герои**; рядом — «Входящие» и настройки.

**Доска** — главы колонками, как в Figma, листаются вбок.
- Сцена добавляется одной строкой («кратко, что происходит») — редактор не открывается.
- Сцены перетаскиваются внутри главы и между главами.
- Клик по сцене — карточка: кратко, ветки, герои, маячки, «Писать эту сцену →».
- Внизу колонки — маячки главы: «✦ посеять здесь» / «◎ раскрыть здесь».
- Сверху — «Показать»: **Всё · Маячки · <ветка>**. Ветка гасит чужие сцены и показывает пунктиром главы, где её нет. «Маячки» — всё, что пока без места раскрытия или пропущено.
- На телефоне доска — лента глав и сцен: открыта глава, где ты сейчас.

**Текст** — открывается там, где остановилась («В прошлый раз: …»).
- Страница пустая: только текст и одна строка сверху — **«Сейчас: …»** (текущий пункт плана) и маячки, которые нужно раскрыть здесь.
- Слева структура книги, справа (кнопка **«План»**) — план сцены на полях: зачем она, по пунктам, маячки, кто в ней и их ещё не использованные цитаты. Редкое — под «Ещё».
- Всё остальное — в меню «⋯»: маячок, режимы, быстрая запись, поиск, «Закончить на сегодня».
- Режимы: **Писать** (только текст), **Править** (страница + материалы, маячки подсвечены), **Переписывать** (прежний текст тихо сбоку, новый пишешь рядом; «оставить новый» или «вернуть старый»).
- **⌘/Ctrl + M** — маячок прямо там, где курсор. Выделение → «✦ Маячок» / «◎ Раскрытие».
- Пока печатаешь — всё вокруг текста гаснет.
- «Закончить» — записка себе на следующий раз.

**Герои** — карточки: пара строк о герое, своя сюжетная ветка, цитаты и реплики.

**Быстрая запись** (⚡ или **⌘/Ctrl + J**): мысль, цитата, диалог, вопрос, маячок. У цитат и диалогов отмечаешь героев — они сами всплывут в главах, где эти герои есть.

**Импорт** .docx / .txt (в том числе выгрузка Фикбука: «===== Часть N =====», сцены по `***`, шапка — в «О книге»). **Экспорт** в Word и в Фикбук по главам.

**Ничего не теряется:** всё пишется на устройство сразу, работает без интернета; версии сцен; при конфликте синхронизации второй вариант уходит в версии.

## Установить на устройства

Сначала приложение нужно опубликовать (см. ниже), потом открыть ссылку:

- **iPhone / iPad** — Safari → «Поделиться» → «На экран „Домой“».
- **Mac** — Safari → Файл → «Добавить в Dock» (или Chrome → значок установки в адресной строке).
- **Windows** — Chrome или Edge → значок установки в адресной строке.

> Важно для iPhone/iPad: Safari может очищать данные сайтов, которые не открывались 7 дней. Установленное на экран «Домой» приложение этого не касается, а синхронизация хранит копию в облаке — включи её.

## Публикация (GitHub Pages — открывается из России без VPN)

1. **Settings → General → Danger Zone → Change visibility → Make public.**
   Публичным становится только код приложения. Тексты в репозитории не хранятся никогда — они живут на устройствах и в личном облаке.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
3. **Actions → Publish to GitHub Pages → Run workflow** (или просто любое обновление `main`).
4. Через пару минут приложение будет по адресу `https://roxz13.github.io/writting-app/`.

Netlify (`netlify.toml`) тоже поддерживается, но из России `netlify.app` открывается нестабильно.

## Синхронизация между устройствами

Настраивается **один раз владельцем**, после этого все (и ты на всех устройствах, и покупатели) просто входят по почте и паролю — никаких ключей.

1. Зарегистрироваться на [supabase.com](https://supabase.com) → **New project** (бесплатно).
2. **SQL Editor → New query** → вставить [`supabase/schema.sql`](supabase/schema.sql) → **Run**.
3. **Authentication → URL Configuration → Site URL**: `https://roxz13.github.io/writting-app/`.
4. **Project Settings → API**: скопировать **Project URL** и **anon public key**.
5. В GitHub: репозиторий → **Settings → Secrets and variables → Actions → Variables → New repository variable**:
   `VITE_SUPABASE_URL` = Project URL, `VITE_SUPABASE_ANON_KEY` = anon key.
6. **Actions → Publish to GitHub Pages → Run workflow**.

Дальше в приложении: **Истории → Настройки → Устройства → Создать аккаунт** (на первом устройстве; придёт письмо — нажать ссылку), на остальных — **Войти**.

Всё пишется сначала на устройство и работает без интернета; когда сеть есть — уходит в облако. Если одну сцену правили на двух устройствах, второй вариант сохраняется в «Версиях».

> Supabase из России может открываться нестабильно — это стоит проверить с телефона без VPN до того, как рассказывать о синхронизации покупателям.

## Разработка

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # тесты синхронизации, импорта и экспорта
npm run build      # сборка в dist/
```

Стек: React + TypeScript + Vite, TipTap (редактор), Dexie/IndexedDB (локальное хранилище), Supabase (облако), vite-plugin-pwa (офлайн и установка).
