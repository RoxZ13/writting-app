# Manuscript.

Рабочий стол автора для тех, кто пишет большие нелинейные истории и теряет нить.
Главная задача — чтобы в любой момент было видно **что я сейчас пишу, зачем, и какие маячки ещё ждут раскрытия**.

Работает в браузере и устанавливается как приложение на iPhone, iPad, Mac и Windows. Без интернета — тоже.

## Как устроено

Одна книга — одно рабочее место. Сверху три вкладки: **Текст · Доска · Герои**; рядом — «Входящие» и настройки.

**Доска** — главы колонками, как в Figma, листаются вбок. Здесь же и планирование:
- **Суть истории** над доской: о чём она, чем закончится, что движет героями.
- **«Пока без места»** — первая колонка: сцены из головы одной строкой, без глав. Потом перетаскиваешь их по местам.
- Новая история начинается с одной колонки **«Вся история»**: расставь сцены по порядку, в карточке сцены отметь **узловые точки ◆** и **накал** (●–●●●●●) — над колонкой рисуется арка «накал сцен».
- **«✂ Новая глава отсюда»** в карточке сцены режет ленту на главы.
- Сцена добавляется одной строкой («кратко, что происходит») — редактор не открывается.
- Сцены перетаскиваются внутри главы и между главами.
- Ctrl+Z / ⌘Z отменяет последнее действие на доске; Ctrl+Shift+Z / ⌘⇧Z возвращает его. На сенсорном экране — «Отменить» в плашке после действия.
- Клик по сцене — карточка: кратко, ветки, герои, маячки, «Писать эту сцену →».
- Внизу колонки — маячки главы: «✦ посеять здесь» / «◎ раскрыть здесь».
- Сверху — «Показать»: **Всё · Маячки · <ветка>**. Ветка гасит чужие сцены и показывает пунктиром главы, где её нет. «Маячки» — всё, что пока без места раскрытия или пропущено.
- На телефоне доска — лента глав и сцен: открыта глава, где ты сейчас.

**Текст** — открывается там, где работа остановилась («В прошлый раз: …»).
- Страница пустая: только текст и одна строка сверху — **«Сейчас: …»** (текущий пункт плана) и маячки, которые нужно раскрыть здесь.
- Слева структура книги, справа (кнопка **«План»**) — план сцены на полях: зачем она, по пунктам, маячки, кто в ней и их ещё не использованные цитаты. Редкое — под «Ещё».
- Всё остальное — в меню «⋯»: маячок, режимы, быстрая запись, поиск, «Закончить на сегодня».
- Режимы: **Писать** (только текст), **Править** (страница + материалы, маячки подсвечены), **Переписывать** (прежний текст тихо сбоку, новый пишешь рядом; «оставить новый» или «вернуть старый»).
- **⌘/Ctrl + M** — маячок прямо там, где курсор. Выделение → «✦ Маячок» / «◎ Раскрытие».
- Выделение → **«В запас»**: кусок уходит из текста в заметку к сцене, с курсивом и абзацами. **Ctrl/⌘ + Z** сразу после этого возвращает текст и убирает заметку. Из «Плана» (раздел «В запасе») или из «Входящих» кусок можно **«Вернуть в текст»** — он встанет туда, где курсор.
- Пока печатаешь — всё вокруг текста гаснет.
- **⌘/Ctrl + F** — найти в сцене, **Ctrl + H** (⌘⇧H на Mac) — найти и заменить. Совпадения подсвечены, «Заменить все» отменяется одной кнопкой. Оттуда же — «Искать во всей книге».
- **Типографика сама:** `-` в начале абзаца → «— », `слово - слово` и `--` → «—», `"` → «ёлочки» (внутри — „лапки“), `<<` `>>` → « », `...` → «…». Вставленный текст из Word или чата причёсывается так же. «⋯» → «Причесать текст» — вся сцена разом.
- Счётчик в углу: слова сцены или выделенного. Клик — знаки с пробелами, авторские листы, время чтения, глава, книга, «сегодня».
- **Кольцо объёма** (по желанию): «История» → «Длина главы» → «Кольцо объёма у счётчика сцены». Слева от счётчика появляется маленькое кольцо — доля сцены в норме главы. Ключевая сцена получает больше места, написанные сцены считаются по факту. На 80 % кольцо теплеет, после 100 % рядом показано, на сколько вышло больше («+1 200»). Без нормы главы бюджет — обычная сцена книги. Пока печатаешь, кольцо гаснет вместе со всем вокруг; на телефоне оно над нижней панелью.
- Норму главы можно задать числом в страницах, знаках или словах — или пресетом площадки: «Фикбук · около 2000 слов», «Author.Today · 15–40 тыс. знаков».
- **⌘/Ctrl + Alt + ↓ / ↑** — следующая / предыдущая сцена. **⌘/Ctrl + /** — все горячие клавиши.
- «Закончить» — записка себе на следующий раз.

**Герои** — карточки: пара строк о герое, своя сюжетная ветка, цитаты и реплики.

**Матчасть** (Герои → «Матчасть»): места, магия, даты, кто что знает. Прикрепляется к героям, главам и сценам и видна в плане этих сцен; упомянутая в тексте запись всплывает сама.

**Тихий вид** (как в Calmly Writer): пока пишешь, только страница; шапка и кнопки — у верхнего края экрана или по Esc. «Aa»: вид, абзац в фокусе, строка по центру.

**Фокус** («⋯» над текстом): 15/25/45 минут только текста — во весь экран, экран не гаснет, на Apple-устройствах одной галочкой «Не беспокоить» (через «Команды»). В конце — сколько слов написано.

**Темп и выкладка** (страница «Книга»): слова по дням, цель на день, прогноз к дедлайну; какая глава следующая на Фикбук, насколько готова и когда по плану.

**Подсказки правки** (режим «Править», кнопка «Подсказки» — сами не включаются): повторы слов рядом, длинные предложения, слова, которые часто можно убрать. Без ИИ — только подсказки.

**Быстрая запись** (⚡ или **⌘/Ctrl + J**): мысль, цитата, диалог, вопрос, маячок. У цитат и диалогов отмечаешь героев — они сами всплывут в главах, где эти герои есть.

**Импорт** .docx / .txt (в том числе выгрузка Фикбука: «===== Часть N =====», сцены по `***`, шапка — в «О книге»). **Экспорт** в Word и в Фикбук по главам.

**Копия:** Настройки → «Скачать копию» / «Вернуть из копии…» (ничего не удаляет). Пока синхронизация выключена, раз в неделю приложение само напомнит.

**Ничего не теряется:** всё пишется на устройство сразу, работает без интернета; версии сцен; при конфликте синхронизации второй вариант уходит в версии.

## Установить на устройства

Сначала приложение нужно опубликовать (см. ниже), потом открыть ссылку:

- **iPhone / iPad** — Safari → «Поделиться» → «На экран „Домой“».
- **Mac** — Safari → Файл → «Добавить в Dock» (или Chrome → значок установки в адресной строке).
- **Windows** — Chrome или Edge → значок установки в адресной строке.

> Важно для iPhone/iPad: Safari может очищать данные сайтов, которые не открывались 7 дней. Установленное на экран «Домой» приложение этого не касается, а синхронизация хранит копию в облаке — включи её.

## Публикация (GitHub Pages — открывается из России без VPN)

1. **Settings → General → Danger Zone → Change visibility → Make public.**
   Публичным становится только код приложения. Тексты в репозитории не хранятся никогда — они живут на устройствах и в личном облаке.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
3. **Actions → Publish to GitHub Pages → Run workflow** (или просто любое обновление `main`).
4. Через пару минут приложение будет по адресу `https://roxz13.github.io/writting-app/`.

Netlify (`netlify.toml`) тоже поддерживается, но из России `netlify.app` открывается нестабильно.

## Синхронизация между устройствами

Истории хранятся в облаке автора — на его Яндекс Диске. Приложение видит только свою папку «Приложения/Manuscript» и ничего больше на Диске.

### Один раз — владелец приложения

1. Открыть [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new) → «Создать приложение».
2. Платформа — «Веб-сервисы». Redirect URI: `https://roxz13.github.io/writting-app/` и `http://localhost:5173/` для разработки.
3. Доступ к данным: «Яндекс.Диск REST API» → «Доступ к папке приложения на Диске».
4. Скопировать **ClientID**.
5. В GitHub: репозиторий → **Settings → Secrets and variables → Actions → Variables → New repository variable**: `VITE_YANDEX_CLIENT_ID` = ClientID.
6. **Actions → Publish to GitHub Pages → Run workflow**.

Без этой переменной ClientID можно вставить прямо в приложении: **Настройки → Своё облако**.

### На каждом устройстве — автор

**Настройки → Своё облако → Яндекс Диск → Подключить.** Откроется страница входа Яндекса. После входа приложение вернётся в настройки.

Вся база лежит на Диске одним файлом. Каждое устройство объединяет его со своими данными: побеждает более свежая правка. Если одну сцену правили на двух устройствах, второй вариант сохраняется в «Версиях» — текст не теряется. Синхронизация идёт при открытии, при возврате в приложение, через 30 секунд после правки и при появлении сети. Всё пишется сначала на устройство и работает без интернета.

Dropbox и Google Диск подключатся так же — позже.

### Старая синхронизация: Supabase

Вход по почте и паролю через [Supabase](https://supabase.com). Она работает, но новые функции под неё не делаются. Из России Supabase открывается нестабильно.

<details>
<summary>Как настроить Supabase</summary>

1. Зарегистрироваться на [supabase.com](https://supabase.com) → **New project** (бесплатно).
2. **SQL Editor → New query** → вставить [`supabase/schema.sql`](supabase/schema.sql) → **Run**.
3. **Authentication → URL Configuration → Site URL**: `https://roxz13.github.io/writting-app/`.
4. **Project Settings → API**: скопировать **Project URL** и **anon public key**.
5. В GitHub: **Settings → Secrets and variables → Actions → Variables**: `VITE_SUPABASE_URL` = Project URL, `VITE_SUPABASE_ANON_KEY` = anon key.
6. **Actions → Publish to GitHub Pages → Run workflow**.

В приложении: **Настройки → Устройства → Создать аккаунт** на первом устройстве, **Войти** — на остальных. Если одну сцену правили на двух устройствах, второй вариант сохраняется в «Версиях».

</details>

## Разработка

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # тесты синхронизации, импорта и экспорта
npm run build      # сборка в dist/
```

Стек: React + TypeScript + Vite, TipTap (редактор), Dexie/IndexedDB (локальное хранилище), Яндекс Диск (облако; Supabase — старое), vite-plugin-pwa (офлайн и установка).
